# Active pause: trigger presses, note selection and feedback flags

Approved by the owner in chat on 2026-10-25 ("LGTM, build it"). Decisions marked "(call)" are
the designer's; everything else is the owner's.

## Intent

The owner reviews maps (mostly generated by their automapper) in practice mode with active pause.
They want to leave structured feedback about a moment, and optionally about specific notes, without
touching a keyboard, and have it land in a machine-readable sidecar file next to the map that the
automapper can later consume (training and evaluation). Screenshots are a nice-to-have.

## Goals

- While active-paused, the trigger of the pointing hand presses whatever that saber points at.
- Select and deselect frozen notes with the saber and trigger; selection is clearly visible.
- A Flag button opens a feedback panel with tap-to-toggle labels in three groups, Save and Cancel.
- Save appends one flag (time, labels, selected notes, screenshot reference) to `flags.json` next
  to the map's `Info.dat`.

## Non-goals and anti-goals

- No free-text entry in VR, no keyboard flows.
- No editing or deleting of saved flags from inside the game (edit the file).
- Must never block or break the active pause itself: a failed screenshot or file write logs, toasts
  once, and leaves the game playable. Nothing here runs outside practice mode.

## Behaviour

### Trigger as "press"

- New `ControllerButton.LeftTrigger` / `RightTrigger` in `Common/ControllerInput`
  (`CommonUsages.triggerButton` per hand; FPFC keyboard fallbacks: right trigger = Space, left
  trigger = Left Ctrl; the debug channel's `button` verb accepts `LT` and `RT`).
- While active-paused: a step button, the Flag button, a feedback label, Save/Cancel and a chapter
  arrow are pressed by the trigger of the hand whose saber ray hits them, or by A (A keeps working).
  The right saber wins when both point at something. UI pointer clicks keep working.
- While playing (not active-paused) nothing changes: chapter arrows still need A.

### Selecting notes

- Targets: colour notes, bombs, chain heads and chain links of the frozen scene. Walls and arcs
  are not selectable (call).
- Hit test: the saber ray against a sphere of 0.28 m around each live target's visual centre; the
  nearest hit along the ray wins; a hovered panel button or chapter arrow takes priority over notes
  (call). Hover shows a subtle highlight on the note so the player knows what the trigger will pick.
- Trigger (or A) toggles the selection of the hovered note. A selected note is unmistakable with
  ghosting on or off: it is drawn un-ghosted (full opacity) with a white glowing halo (call: a small
  additive quad or ring at the note, implementer's choice of exact look).
- Selection persists across steps and resume until the player deselects, presses "Clear" on the
  panel, or leaves the song. Identity is the map data of the note (beat time, line index, layer,
  colour, cut direction, kind), so a note stays selected when it is respawned by a seek or resume.
- Selection is only possible while active-paused; the highlights stay visible while playing (they
  move with the notes) (call).

### The Flag panel

- The step panel gains a third row: `Flag` (label shows the selected count, e.g. `Flag (2)`) and
  `Clear` (deselects everything; disabled look when nothing is selected) (call).
- `Flag` swaps the panel to the feedback panel (same canvas position, larger plate):
  three columns of toggle buttons, lit gold when on, several may be on:
  - Good: `good_pattern` "Good pattern", `good_difficulty` "Good difficulty", `good_timing`
    "Good timing", `good_flow` "Good flow", `fun` "Fun".
  - Bad: `too_easy` "Too easy", `too_hard` "Too hard", `timed_poorly` "Timed poorly",
    `impossible_pattern` "Impossible pattern", `bad_flow` "Bad flow", `awkward_hands`
    "Awkward hands", `too_dense` "Too dense", `too_sparse` "Too sparse".
  - Note: `repetitive` "Repetitive", `surprising` "Surprising", `mismatches_music` "Doesn't
    match the music", `check_other_difficulties` "Check other difficulties".
  - Bottom row: `Save` and `Cancel`. Save with no label and no note is allowed (a plain bookmark)
    (call).
- Save writes the flag, shows a toast ("Flag saved: 2 labels, 3 notes"), clears the lit labels
  (the note selection stays), and returns to the step panel. Cancel returns without saving.
- Resuming (X) or the pause menu while the feedback panel is open behaves like Cancel (call).

### The file

- Path: `flags.json` next to the map's `Info.dat` (same place as `chapters.json`). Resolved from
  the played level's custom level path; non-custom (OST/DLC) levels cannot be flagged: the Flag
  button is hidden and a toast says why on the first attempt (call).
- JSON object:
  ```json
  {
    "version": 1,
    "levelId": "custom_level_<hash>",
    "songName": "...",
    "flags": [
      {
        "id": "20261025-143012-7f3a",
        "createdAt": "2026-10-25T19:30:12Z",
        "characteristic": "Standard",
        "difficulty": "Expert",
        "songTime": 42.317,
        "beat": 96.0,
        "speed": 1.0,
        "labels": ["too_dense", "awkward_hands"],
        "notes": [
          { "kind": "note", "beat": 96.0, "time": 42.317, "lineIndex": 1, "lineLayer": 0,
            "color": "red", "cutDirection": "down" }
        ],
        "screenshot": "flags/20261025-143012-7f3a.png"
      }
    ]
  }
  ```
  `kind`: `note`, `bomb`, `chain_head`, `chain_link`; `color`: `red`, `blue` (bombs: `none`);
  `cutDirection`: `up`, `down`, `left`, `right`, `up_left`, `up_right`, `down_left`,
  `down_right`, `any`, `none`. `beat` is the map's beat time (BPM changes included, the same
  tempo map Chapters uses); `time` is song seconds. `screenshot` is relative to the map folder or
  null. Unknown keys must be preserved by readers; the mod only appends.
- Writes: read-modify-write of the whole file, written to a temp file then moved into place. A file
  that does not parse is renamed to `flags.json.corrupt-<timestamp>` and a fresh one started, with
  a log line and a toast (call).
- Screenshot: `ScreenCapture.CaptureScreenshot` into `flags/<id>.png` beside the file (the mirror
  view in VR; the desktop view in FPFC). Failure to capture never fails the save; the flag then has
  `"screenshot": null`.
- The format is documented for the automapper in `docs/flags.md` (owner-facing, concise).

## Constraints

- Practice mode only, like the rest of active pause; everything inside callbacks under `Guard`.
- Core (`src/MaxTweaks.Core/ActivePause/Flags/`) holds the label catalogue, the note key and flag
  model, serialization (Newtonsoft 13.0.2) and id generation, with xUnit tests; no Unity types.
- ASCII only, LF, Conventional Commits, direct push to main, release zip on green.
- Auto-reload must ignore `flags.json` and `flags/` writes (they must not count as a map change).

## Left to the builder

- Exact halo look, panel sizes and colours (keep the existing panel style).
- Whether a debug-channel verb is added to select the n-th live note for FPFC QA (recommended:
  `select-note <n>` and `flag-labels <ids>`), documented in docs/qa.md if added.
- Log lines: `[ActivePause] selected <kind> at <time>s` / `deselected`, `[ActivePause] flag saved
  <id> at <time>s: <n> labels, <m> notes[, screenshot]`, `[ActivePause] flag file error: ...`.
